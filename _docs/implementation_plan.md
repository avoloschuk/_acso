# План реалізації: Оновлення веб-сайту ВГО «АСН» (ACSO)

## Резюме проєкту

**Мета:** Перенести існуючий застарілий WordPress-сайт (samoorg.com.ua) на сучасну, чисту платформу WordPress із новим дизайном відповідно до затвердженого брендбуку ACSO.

**Ключовий принцип:** Стандартний WordPress на хостингу, мінімум платних плагінів. Редактор сторінок для контент-менеджера — **Elementor (free)** згідно з ТЗ. Оболонка сайту (header/footer, CPT, архіви) — **child theme** з CSS/HTML прототипу (`prototype/`). Gutenberg лишається в ядрі WP, але не основний інструмент верстки landing-сторінок. Розробник веде тему через Git.

---

## 1. Архітектура: WordPress + Hello Elementor + Child Theme + Git

### Що це означає
- **WordPress:** Остання стабільна версія, окремий staging-subdomain, окрема БД.
- **Тема:** **Hello Elementor** + **acso-child** — глобальні стилі з `prototype/style.css`, header/footer, шаблони single/archive для CPT.
- **Elementor (free):** головна та статичні landing-сторінки; збережені шаблони/Kit (кольори брендбуку).
- **Потоковий контент** (новини, аналітика, бібліотека): переважно **шаблони теми** + простий редактор поста (без Elementor на кожну статтю).
- **Плагіни (мінімум, free де можливо):** Elementor, Yoast або Rank Math, Polylang (замість платного WPML — за погодженням), Contact Form 7, Redirection; CPT реєструються в `functions.php` теми.

### Зона відповідальності розробника (що лежить у Git)
```
wp-content/themes/acso-child/
├── style.css           # Child theme + бренд-стилі (з prototype/)
├── functions.php       # CPT, таксономії, хуки
├── header.php
├── footer.php
├── front-page.php      # або Elementor template ID
├── single-{cpt}.php
├── archive-{cpt}.php
└── assets/
    ├── logo_icon_color.png
    └── script.js
```

Усе інше (ядро WordPress, плагіни, база даних) живе на сервері і оновлюється через адмінку.

### Backward Compatibility
- Оновлення ядра WordPress та плагінів через адмінку **не зачіпає** код теми.
- Усі кастомні правки робляться через `functions.php` за допомогою хуків (`add_action`/`add_filter`), а не правкою коду плагінів.
- При оновленні плагінів ваші зміни **не стираються**.

## 2. Міграція даних зі старого сайту

### Проблема
Старий сайт — WordPress 5-10-річної давності з купою плагінів (Elementor, Gutenberg старих версій). База даних засмічена шорткодами та сміттям від видалених плагінів.

### Рішення: ETL (Extract → Transform → Load)
1. **Extract:** Вивантажуємо зі старого сайту лише корисні дані: пости, сторінки, категорії, теги, медіафайли (через WP All Export або стандартний WordPress Export).
2. **Transform:** Пишемо Python/PHP-скрипт, який очищує HTML від застарілих шорткодів Elementor та перетворює контент на чисті блоки Gutenberg.
3. **Load:** Імпортуємо очищені дані на новий чистий сайт (через WP All Import або стандартний імпорт).

### Пріоритети міграції
| Пріоритет | Контент | Вимоги до якості |
|---|---|---|
| 🔴 Критичний | Статті за останні 6 місяців | Ідеальний вигляд, без багів |
| 🟡 Важливий | Статті за останній рік | Перевірено, допустимі мінімальні відхилення |
| 🟢 Бажаний | Статті старіші за рік | Перенесено "як є", допустимі візуальні баги |

### Додаткові кроки міграції
- **Медіафайли:** Копіюємо `wp-content/uploads/` на новий сервер, оновлюємо шляхи через Better Search Replace.
- **SEO-редиректи:** Масові 301-редиректи зі старих URL на нові (плагін Redirection), щоб не втратити позиції в Google.

## 3. Автоматизоване тестування (Playwright)

Після міграції контенту запускаємо автоматичні тести:

### Visual Regression Testing
- Скрипт відкриває топ-100 статей за останні 6 місяців на **старому** сайті → робить скриншоти.
- Відкриває ті самі статті на **новому** тестовому сервері (Staging) → робить скриншоти.
- Порівнює піксель-в-піксель. Виявляє "попливші" стилі, зниклі зображення, зламану верстку.

### Link & 404 Validation
- Скрипт обходить усі сторінки нового сайту.
- Перевіряє кожне посилання на відсутність 404 (битих посилань).
- Генерує звіт з переліком проблемних URL.

## 4.1. Маппінг прототипу на WordPress (чернетка — очікує підтвердження scope замовником)

Прототип (`prototype/`) — еталон верстки. HTML/CSS переносяться в `acso-child`; контент живе в WordPress і редагується з адмінки, без коду.

| Сторінка прототипу | Сутність у WordPress | Як редагується |
|---|---|---|
| `index.html` — Головна | Page + Elementor | Блоки: перестановка, приховування, тексти, кнопки |
| `about.html` — Про нас | Page + Elementor | Команда — CPT `team_member`; партнери — CPT `partner`; звіти — PDF у медіатеці |
| `democracy.html` — Місцева демократія | Page + Elementor | Тематичні блоки, практики, FAQ |
| `analytics.html` / `analytics-single.html` | CPT `analytics` + `archive-analytics.php` / `single-analytics.php` | Запис: заголовок, текст, обкладинка, автори, напрям, PDF |
| `library.html` | CPT `library` + `archive-library.php` | Запис: назва, обкладинка, рік, напрям, PDF |
| `news.html` / `news-single.html` | CPT `asn_news` + шаблони теми | Текст, галерея, відео, файли — стандартні блоки редактора |
| `partners.html` | CPT `partner_post` + прив'язка до ресурсного центру | Редактор РЦ — лише свої матеріали, премодерація |
| `network.html` / `center.html` | CPT `resource_center` (назва, область, координати, контакти, координатор) | Карта будується автоматично із записів центрів |
| Тематичні фільтри | Єдина таксономія «Тематичні напрями» для всіх CPT | Адмін створює/перейменовує напрями |
| `search.html` | Стандартний пошук WP, `search.php` | — |
| Header / footer | `header.php` / `footer.php` | Меню (з підменю) — «Зовнішній вигляд → Меню», окремо UA/EN (Polylang) |
| Шапка розділу (картинка, заголовок, опис) | Обкладинка та опис сторінки розділу | З адмінки |
| Контактна форма | Contact Form 7 + згода на обробку даних + antispam | Отримувачів змінює адмін |
| `ui-states.html` — стани елементів | CSS теми + закрита сторінка-стайлгайд | — |

**Обмеження Elementor free:** немає Slides, Posts, Theme Builder, Forms (це Pro). Pro не закладаємо → у `acso-child` власні віджети Elementor:
hero-слайдер, сітка карток (останні N з розділу / за напрямом / ручний вибір), напрями діяльності, карта ресурсних центрів, команда, партнери, список файлів.
Менеджер додає віджети в Elementor і заповнює поля; дані беруться із записів WordPress.

**Фідбек 2.0 не змінює цю схему** і не потребує окремого плагіна чи Elementor Pro. Новий вигляд — це ті самі віджети в `acso-child`:

- шапка — `header.php` і меню WordPress (без пункту «Головна»; підпис пункту «Мережа РЦ»);
- hero-слайдер — перший слайд з полів віджета, наступні слайди з позначених featured записів `asn_news`;
- «Напрями діяльності» — карусель по термінах таксономії;
- плитка новини з фото — той самий віджет карток, інший шаблон вигляду;
- карта — маркери з координат CPT `resource_center` (16 центрів з чинного переліку мережі на samoorg.com.ua);
- «Про нас»: кнопки документів, організаційна структура, команда без особистих контактів, 9 річних звітів — секції Elementor і віджет файлів.

**Ролі:** «Редактор РЦ» — лише записи свого центру; адмін може обмежити самостійну публікацію; матеріали партнерів — на премодерацію.

## 6. Git-воркфлоу та CI/CD (Деплой)

### Два середовища
- **Staging** (тестове): для перевірки змін перед запуском.
- **Production** (робоче): фінальний сайт для відвідувачів.

### Процес оновлення
1. Розробник вносить зміни в код теми локально в IDE.
2. `git commit` → `git push` у відповідну гілку.
3. **GitHub Actions** автоматично деплоїть:
   - Гілка `develop` → Staging сервер.
   - Гілка `main` → Production сервер.
4. Перевірка на Staging → мердж у `main` → автоматичний деплой.
