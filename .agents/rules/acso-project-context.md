# ACSO (ВГО АСН) — контекст проєкту

## Мета
Перенести **samoorg.com.ua** (legacy WordPress) на новий WordPress з брендбуком ACSO, прототипом головної та мінімумом платних плагінів. Не headless, не React-фронт — класичний WP для контент-менеджерів.

## Джерела правди (пріоритет)
1. `_docs/ТЗ сайт.docx` — функціональні вимоги замовника
2. `_docs/implementation_plan.md` — технічна архітектура (оновлена під Elementor)
3. `prototype/` — затверджений візуал головної (`index.html`, `style.css`, assets)
4. `_docs/brandbook_assets/`, `design_tokens.css` — бренд
5. `_docs/структура сайту.docx` — ієрархія розділів
6. `_agreement/` — договір, строки, етапи оплати

Якщо **client_proposal.md** суперечить ТЗ або `implementation_plan.md` (напр. «без Elementor») — **керуватися ТЗ + implementation_plan + рішенням команди: Elementor free для landing**.

## Строки (договір, орієнтир)
- **01.10–31.10** — дизайн і погодження (прототип головної вже є; потрібні типові inner-шаблони)
- **01.11–10.12** — технічна реалізація + перенесення даних
- **11.12–31.12** — тест, запуск, передача, інструктаж
- **30 днів** — гарантійні виправлення після акта

## Секрети та доступи
- Лише **`secrets/acso.env`** (локально, у `.gitignore`). **Ніколи** не виводити значення в чат, коміти, логи, скриншоти.
- У shell: `set -a && source secrets/acso.env && set +a` — без echo паролів.
- Шаблон для репо: `secrets/acso.env.example` (без секретів).
- Prod не чіпати до cutover; перед міграцією — **повний бэкап** (cPanel + БД + uploads).

## Організація
- Замовник: ВГО «Асоціація сприяння самоорганізації населення»
- Старий домен: **samoorg.com.ua**
- Staging: окремий **subdomain + окрема БД** (не WP у підпапці prod без ізоляції). На shared — **одна PHP на акаунт** (prod+staging); MySQL на skm352 — OK для WP 6.x.

## Мова роботи агента
- Документація клієнта — українською; з розробником можна російською/англійською.
- Публічний UI сайту — **UA основна**, **EN** друга (Polylang або аналог за погодженням).
